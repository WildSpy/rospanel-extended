## Что это

РосПанель — самостоятельная панель для [Xray-core](https://github.com/XTLS/Xray-core). Она управляет пользователями, протоколами, подписками, маршрутизацией, тарифами и резервными копиями через веб-интерфейс. При необходимости к мастеру подключаются дополнительные ноды. Панель и Xray работают на вашем сервере; VPN-клиент в состав проекта не входит.

Один бинарник включает веб-интерфейс и API. Для панели доступны автоматические TLS-сертификаты через ACME, в том числе для IP-адреса при поддержке центром сертификации. Для **переезда мастера требуется домен**: прежние ссылки подписок сохраняются благодаря переключению его DNS-записи.

## Установка

### Скрипт и systemd

На Linux-сервере выполните:

```bash
curl -Ls https://raw.githubusercontent.com/WildSpy/rospanel-extended/main/install.sh | sudo bash
```

Скрипт скачает релиз, установит сервис и предложит указать домен. Если домена нет, оставьте поле пустым для работы по IP. Домен можно передать заранее через `ROSPANEL_HOST`.

Для ручной установки:

```bash
curl -fsSL -o rospanel https://github.com/WildSpy/rospanel-extended/releases/latest/download/rospanel-linux-amd64
chmod +x rospanel
sudo ./rospanel install
journalctl -u rospanel | grep -A6 FIRST-RUN
```

Для ARM замените `amd64` на `arm64`. Установщик выводит адрес панели в журнал. Первый вход: `admin` / `admin` по пути `/rospanel/`; мастер настройки потребует сменить пароль и предложит установить секретный путь. После смены пути сохраните новый адрес: по корню сайта форма входа не открывается.

### Docker

```bash
docker run -d --name rospanel \
  --network host \
  --cap-add NET_ADMIN \
  --device /dev/net/tun \
  -v rospanel-data:/data \
  ghcr.io/wildspy/rospanel-extended:latest
```

`NET_ADMIN` и `/dev/net/tun` нужны для AmneziaWG и других возможностей, которым требуется TUN. Для постоянной установки подготовьте доступ к данным и перезапуск контейнера средствами Docker.

### Переход с AppsGanin/rospanel

Форк открывает базу upstream на месте: пользователи, настройки, ноды и ссылки подписок сохраняются. Миграции, уже применённые upstream, повторно не выполняются — у форка те же миграции лежат под другими номерами, и он сопоставляет их при запуске. Сначала переведите мастер, затем ноды: ноды upstream продолжают работать с мастером форка, пока вы их не переключите.

**1. Мастер.** На сервере панели:

```bash
sudo rospanel backup /root/rospanel-before-fork.tar.gz
curl -Ls https://raw.githubusercontent.com/WildSpy/rospanel-extended/main/install.sh | sudo bash
```

На вопрос о домене оставьте поле пустым — домен из базы сохраняется. Сообщение `first-run credentials not captured` на существующей базе ожидаемо: логин и пароль остаются прежними. Проверьте `rospanel status`, отсутствие ошибок `migrate` в `journalctl -u rospanel -n 50`, вход в панель, пользователей и подписки.

**2. Ноды.** Агент upstream обновляется только из репозитория AppsGanin и только на более новую версию, поэтому панель форка обновить его не может: на вкладке **Серверы** такие ноды помечены «агент новее панели». Один раз выполните на каждой ноде:

```bash
curl -Ls https://raw.githubusercontent.com/WildSpy/rospanel-extended/main/install.sh | sudo bash -s -- --update-node
```

Команда скачивает релиз форка, сверяет его с `SHA256SUMS`, сохраняет прежний бинарник как `/usr/local/bin/rospanel.prev` и перезапускает `rospanel-node`. Данные ноды и её подключение к мастеру сохраняются, добавлять ноду заново не нужно; через несколько секунд в панели появится версия форка. Дальше ноды обновляются из панели как обычно. Вернуть прежний агент: `sudo mv -f /usr/local/bin/rospanel.prev /usr/local/bin/rospanel && sudo systemctl restart rospanel-node`. Контейнерную ноду переведите пересозданием контейнера с образом `ghcr.io/wildspy/rospanel-extended` на том же томе данных.

**Что учесть.**

- Версии форка нумеруются отдельно от upstream (форк 5.12.x включает upstream 5.19.x), поэтому номера двух проектов сравнивать нельзя.
- Встроенный REALITY выключается, если у него нет ключа или адрес назначения пустой либо `max.ru`.
- NaiveProxy и Mieru в форке по умолчанию выключены, но при переходе сохраняются ваши настройки upstream.
- Обратный переход на upstream — только восстановлением резервной копии, сделанной до перехода: после запуска форка upstream не узнает записи миграций в базе.

[Руководство по переезду](docs/MIGRATION.md) описывает перенос уже работающего мастера РосПанели между серверами.

## Ноды

В панели откройте **Серверы → Добавить ноду** и выполните выданную команду на новом сервере. Токен присоединения одноразовый и действует 24 часа. Доступна также установка по SSH. Ноде нужен исходящий доступ к мастеру; клиентские подключения приходят на саму ноду. Для нестандартного TLS панель может предложить установку с `--insecure` — используйте это только для доверенного мастера.

Ноды получают конфигурацию и пользователей от мастера. Статус локального агента проверяется командой `rospanel node status`. Контейнерную ноду обновляйте новым Docker-образом с пересозданием контейнера; её данные должны оставаться на постоянном томе. При переезде мастера его публичный домен сохраняется, поэтому повторное присоединение нод обычно не требуется.

Для отдельного VLESS-профиля с входом в стране клиента и произвольным числом серверов используйте [Мульти-хоп](docs/MULTIHOP.md).

## Переезд мастера

Функция рассчитана на мастер с **доменом**, через который уже выданы подписки и подключены ноды. Технический адрес нового сервера (IP:порт) используется только для связи между мастерами и не попадает в ссылки клиентов.

1. На старом мастере откройте **Управление → Переезд мастера**, укажите адрес кандидата и режим изменения DNS.
2. Запустите на новом сервере команду установки кандидата, которую выдаст панель. Токен сопряжения действует 15 минут.
3. Проверьте доступность кандидата из панели и отдельно проверьте его сетевые порты, сертификат для публичного домена и работу протоколов. Встроенные проверки не заменяют эти проверки на новом сервере.
4. После переключения обновите A/AAAA-записи домена, если выбран ручной режим DNS. Убедитесь, что подписка и VPN работают через прежний домен.
5. Сохраняйте старый сервер на время обновления DNS-кэша и отключайте его после проверки клиентов и нод.

Перед переключением сделайте независимую резервную копию. Возврат DNS на старый сервер после появления новых данных на новом мастере может привести к их потере. Подробности и аварийное восстановление: [руководство по переезду](docs/MIGRATION.md).

## Возможности

### Подключения и подписки

- **Протоколы:** VLESS Vision, VLESS XHTTP REALITY, NaiveProxy, Mieru, Snell v5/v6, Hysteria2 с переключением портов, AmneziaWG 3.1, MTProto-прокси для Telegram (fake TLS и WEB-прокси); доступны собственные inbound-конфигурации.
- **TLS и маскировка:** ACME-сертификаты, домены прикрытия и настройки транспорта через панель.
- **Пользователи:** лимиты трафика и скорости, сроки действия, группы, ограничения по IP и опциональная привязка устройств по HWID.
- **Подписки:** форматы для популярных клиентов, правила, ротация токена, режим обслуживания и настройка отображаемых серверов.
- **Страница подписки:** собственный внешний адрес для браузеров, настройка видимости конфигураций и Clash; пользовательское соглашение и политика конфиденциальности в Markdown.
- **Внешние подписки:** импорт и использование внешних прокси; поддержка Happ Subscription (crypt1–5 и outbounds).

NaiveProxy и Mieru по умолчанию выключены и включаются в настройках подключений.
NaiveProxy использует TLS-порт VLESS и требует доверенного сертификата; Mieru получает
собственный TCP-порт. Ссылки выдаются с учётом возможностей клиента.

**Snell** (протокол Surge) — версии 5 и 6 на выбор, встроенный сервер без внешних
бинарников. Клиент Snell знает о пользователе только ключ, поэтому у каждого
пользователя свой TCP-порт (первый порт + номер пользователя, по умолчанию с 61000) и
ключ — его UUID; диапазон открывается в фаерволе автоматически. v5 поддерживает
обфускацию http/tls и клиентов v4, v6 — режимы `default` и `unshaped`. По умолчанию
включается v5 с обфускацией TLS: v6 трафик не маскирует, и из сетей в России
большинство его соединений обрывается на первом пакете. Трафик идёт
через Xray с учётом, лимитами и маршрутизацией. Ссылка `snell://` — в формате
Shadowrocket. Включается в «Подключения → SNELL» на мастере и на каждой ноде.

**MTProto (прокси Telegram)** работает на собственном TCP-порту с fake TLS: Telegram
подключается к серверу без VPN-приложения, у каждого пользователя свой секрет,
а трафик выходит через Xray, поэтому маршрутизация, учёт, лимиты и отключение
работают как у остальных подключений.

**WEB-прокси Telegram** — новый тип прокси в Telegram (Desktop 7.1+, Android, iOS).
Клиент не открывает своего MTProto-соединения: скрытая страница на домене сервера
передаёт его потоки по HTTPS (WebSocket, порт 443), и снаружи это обычный сайт.
Включается в «Подключения → MTProto → WEB-прокси Telegram»; нужен собственный домен
сервера с доверенным сертификатом на порту 443. Режим «Только WEB» не открывает
отдельного порта fake TLS. Пользователи получают ссылку `tg://webproxy` с секретом
`dd…` в отдельной карточке на странице подписки, рядом с обычной `tg://proxy` для
старых версий приложения. Запрос без верного ключа видит сайт-прикрытие. Ноды
поддерживают WEB-прокси после обновления агента.

### Сеть и управление

- **Маршрутизация:** правила выхода, WARP, Opera и пулы прокси с контролем доступности и ограничением прямого выхода.
- **Мультинода:** отдельные параметры серверов, распределение пользователей и наблюдение за состоянием нод.
- **Тарифы и оплаты:** гибкие планы, дополнительные устройства и пакеты трафика, кошелёк, промокоды и реферальная программа. Провайдеры включают YooMoney и Telegram Stars; доступны журнал платежных уведомлений и анализ подозрительной активности.
- **Администрирование:** роли, TOTP, аудит действий, резервные копии и восстановление.
- **Интеграции:** Telegram-бот с Mini App, мастер подключения, автоматические сообщения, общий чёрный список и аналитика источников регистрации; HTTP API, вебхуки с очередью доставки в БД, рассылки во внешние системы, MCP, метрики Prometheus и [дашборд Grafana](docs/grafana/rospanel.json). Описание API: [docs/api.md](docs/api.md).
- **Эксплуатация:** обновления панели и нод по расписанию (по умолчанию выключены), диагностика, обнаружение злоупотреблений, уведомления, брендинг и интерфейс на русском и английском языках.

## CLI

```text
rospanel install                 установить и запустить systemd-сервис
rospanel uninstall [-y]         удалить сервис с сохранением данных
rospanel backup [файл]          создать резервную копию
rospanel restore [-y] <файл>    восстановить данные из копии
rospanel disaster-recover --from <файл> [--passphrase <пароль>]
                                 восстановить мастер после аварии
rospanel node install --join '<URL>'  присоединить ноду
rospanel node status            проверить локальную ноду
rospanel node set-panel <URL>   сменить адрес мастера для ноды
rospanel node uninstall [-y]   удалить сервис ноды
```

Восстановление из резервной копии требует перезапуска сервиса. Команды установки и управления сервисом выполняются с правами root. Актуальные параметры доступны через `rospanel help` и справку конкретной команды.

## Архитектура

Мастер хранит состояние в SQLite, отдаёт веб-панель и API, управляет Xray и синхронизирует ноды. Нода запускает Xray и локальный агент; связь с мастером инициирует сама нода. Для подписок и связи нод с мастером используйте стабильный публичный домен.

## Разработка

Нужны Go версии из [go.mod](go.mod), Node.js 24.22.1 LTS (или совместимая более новая версия) и npm. Веб-интерфейс находится в `web/`.

```bash
cd web && npm ci && npm run build
cd ..
go test ./...
```

История изменений — в [CHANGELOG.md](CHANGELOG.md), правила коммитов — в [.agents/rules/changelog-and-commits.md](.agents/rules/changelog-and-commits.md).

## Дисклеймер

Программное обеспечение предназначено для законного использования на собственных серверах. Администратор отвечает за соблюдение местного законодательства, правила провайдера и защиту данных пользователей. Проект предоставляется без гарантий; перед обновлением и переездом сохраняйте резервную копию.
